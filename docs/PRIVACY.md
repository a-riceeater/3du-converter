# Working with private drill files

Real drills belong to real ensembles. This repository contains **only** source code,
documentation and synthetic data generated by the tests.

## Rules

- Keep real `.3du`, `.3dudb`, extracted JSON, converted outputs and music **outside** the
  repository, for example `~/drill-private/`.
- Never commit, upload, screenshot into docs, or paste real drill content into issues or logs.
- Do not send drill files to online converters, APIs or telemetry.
- Before opening a converted drill in an app with analytics, turn analytics off. OpenMarch
  records sessions when analytics are on.

## Safeguards in this repository

1. **`.gitignore`** covers drill extensions in any capitalization and at any depth:
   `.3du`, `.3dudb`, `.dots`, `.fieldwork(s)`, `.om/.omz/.omt`, plus extracted datasets,
   archives, audio, SQLite and pickle dumps, and private directories.
2. **`scripts/check-private-data.sh`**, run by the pre-commit hook, blocks files that look
   private even when renamed:
   - private extensions;
   - `3DUD`, SQLite, ZIP, gzip and audio signatures;
   - JSON or text containing drill datasets;
   - files over 1 MiB;
   - any term listed in a local, gitignored `.private-denylist`, such as your ensemble's name.
   ```sh
   sh scripts/install-hooks.sh                 # once per clone
   sh scripts/check-private-data.sh --tracked  # audit everything already tracked
   ```
3. **CI** runs `--tracked` on every push and tests only synthetic fixtures.
4. **Tests** build synthetic `.3du` files in memory (`three_du_core::synth`). No binary
   fixtures are committed.

## Testing against a real file, privately

```sh
THREE_DU_PRIVATE_SAMPLE=~/drill-private/show.3du \
THREE_DU_PRIVATE_ORACLE=~/drill-private/show_extracted.json \
cargo test -p three-du-core --test private_regression -- --nocapture
```

The test prints only aggregate counts and match statistics. It writes nothing to disk.

## Command-line behavior

- `inspect` hides the title, set names and labels unless you pass `--reveal`.
- Diagnostics never include names.
- The input file is opened read-only.
- Outputs go to a temporary sibling first and are renamed into place only after validation.
- Existing files are never replaced without `--overwrite`.
